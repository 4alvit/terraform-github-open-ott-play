# Complete supported local-execution TLS profile

This profile covers the maintained Terraform configurations, their GitHub provider calls, registry/module downloads and HCP remote-state connections when execution occurs in the operator's local, verified process. It does not require a live apply to validate cryptographic behavior. Source releases and tests do not alter infrastructure.

## Exact runtime and configuration

Use the official Terraform **1.16.5** binary built with **Go 1.26.8**, the locked integrations/github **6.13.0** provider built with **Go 1.26.4**, and a supported Linux runtime. Verify downloaded package SHA-256 values using the publisher's authenticated checksum manifest and inspect the actual executable metadata with `go version -m /absolute/path/to/binary`. Preserve `.terraform.lock.hcl`; provider upgrades need new review. Verify every installed provider executable, not only the Terraform command on PATH.

Run Terraform with this process-scoped environment assignment:

```sh
GODEBUG=fips140=on terraform version
GODEBUG=fips140=on terraform init -lockfile=readonly
```

Use the same assignment for separately approved plan/apply/import operations. The provider subprocess inherits it. The setting applies to this process and its children and does not change machine-wide policy. It is a Go runtime mode, not a claim that this project has FIPS certification. Do not substitute an older or custom binary that may ignore the setting.

For an HCP workspace, use **Local execution mode** so the verified Terraform and provider process performs the operation while HCP stores state. Changing execution mode or applying a plan requires the normal separate infrastructure review. A remote HCP runner, agent image or other operating system does not inherit this workstation's environment or evidence; qualify its binaries and policy separately before claiming this profile. All four maintained repositories use the same GitHub provider family; provider aliases must retain this policy too.

Use the normal HTTPS registry, HCP and GitHub endpoints with hostname and CA verification. Do not enable insecure certificate flags, custom plaintext endpoint overrides, or unreviewed proxy interception. Any private trust anchor must meet the same key requirements. GitHub personal/fine-grained tokens are credentials supplied by the issuer, not project-generated encryption keys. Actions secrets use the provider's standard NaCl sealed-box implementation (Curve25519/XSalsa20-Poly1305), and the project does not implement a custom cipher. Existing webhook HMAC secrets must contain at least 32 randomly generated bytes, shared with the receiver through a private channel; do not rotate a production secret just to import it.

The Go TLS policy retains TLS >=1.2, authenticated certificate validation and approved cipher/key exchange mechanisms. It rejects RSA certificate keys below **2048 significant bits** throughout the selected chain; supported elliptic curves and symmetric mechanisms meet the through-2030 minimum. The project does not generate a weaker default key. This is a usable complete configuration; ordinary defaults and unrelated optional deployment tools are not represented as identical.

## Reproducible isolated verification

`scripts/test_tls_profile.py` runs the real Terraform module downloader and real GitHub provider in a temporary configuration with no cloud/backend block. A local HTTPS fixture receives only synthetic credentials; a temporary filesystem mirror contains the verified provider. The test executes a read-only plan against that fixture, never a production API or apply.

- RSA-2048 works with both ordinary and strict clients.
- RSA-2047 works in the ordinary client calibration.
- The strict downloader rejects RSA-2047 before an HTTP request.
- The strict provider rejects RSA-2047 before the synthetic Authorization header is sent.

Run on Linux after installing `cryptography==50.0.2` and the verified binaries:

```sh
TLS_TEST_TERRAFORM=/absolute/path/to/terraform \
TLS_TEST_PROVIDER_DIR=/absolute/path/to/extracted/provider \
TLS_TEST_PLATFORM=linux_amd64 python3 scripts/test_tls_profile.py
```

The October 2026 Linux ARM64 run passed all eight calibration/strict combinations. CI repeats them on Linux AMD64. The test does not establish deployed workspace policy or confidential handling by external hosted services.
